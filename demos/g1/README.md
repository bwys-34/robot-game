5. 起身：恢复站姿，松开输入后再接管。
6. 表演：切到动作表演，RB + A/B/X/Y 或舞蹈卡完成一段舞蹈。

## 表演音效与转向跟随（2026-11-07，本地预览历史）

入口：`http://127.0.0.1:8765/demos/g1/drive/?v=2026-11-07-performance-audio-2`。本轮未提交、推送或上线，覆盖下节 gait-audio-1 本地预览。

工具栏点“开启音效”后，十五个动作都有同步声音。`src/drive-action-audio.ts` 根据实际动作段时长建立音效标记：律动为鼓点，机械舞为机械节奏，双臂摆舞为旋律与轻拍，加油舞为拍手与鼓点；其他动作配轻机械音、挥动音、提示音。鼓掌的三个拍点对齐手掌合拢；跳跃和后空翻共享 `BODY_CLIP_TIMING` 的起跳/落地时刻，蹲坐共享下降/起身时刻。`DriveRig.actionSounds` 只含当前帧事件，`DriveActionSoundClock` 跟随姿态时间推进，暂停时不另跑音频节拍；卡帧超过 0.14 秒的旧事件丢弃。`DriveSoundBank` 复用噪声缓冲合成八类表演音，最多同时 16 个声音节点；暂停、切模式、倒地和复位取消表演，正常结束保留尾音。默认静音及用户手势开启、失焦后手动恢复的规则不变。这是合成音效，非宇树实机录音，也未引入背景音乐文件。

相机此前把画布任意 pointerdown 都当作自由观察，因此聚焦点击也取消转向跟随。`DriveScene` 现在区分游客明确选择的全景与临时拖动观察：单击保持跟随；实际移动至少 5px 或双指操作才临时观察；松手后驾驶或转向恢复平滑跟随。明确点击“全景”后继续驾驶不会自动跳回，点击切回“跟随”或原手柄相机键恢复。切换清除 OrbitControls 遗留角速度，复用 `OrbitGestureGuard` 处理取消和后台中断，避免旧触点阻断跟随。

## 驾驶手脚联动与音效（2026-11-07，本地预览）

用户选择先做手脚联动和短音效。本轮预览：`http://127.0.0.1:8765/demos/g1/drive/?v=2026-11-07-gait-audio-1`，尚未推送或上线；下节保留当前正式发布说明。仅构建驾驶页，不把原 G1 页其他未发布编辑带入。

`DRIVE_GAIT_CONFIG`（`src/drive-config.ts`）集中肩部站姿、最大摆幅、局部脚间距到摆臂的增益、肘部跟随与阻尼。`DriveRig` 把左右脚差值投影到机器人局部前后轴，驱动对侧手臂，避免把世界 Z 轴误作前进轴；侧移、原地转身及持续踏步按当前摆脚相位小幅摆臂。脚底求解、关节限位、十五动作与两套输入映射不变。停止与模式切换通过原阻尼回收，表演仍由原动作时间线接管。这是作者设置的教学步态，不复现某一固件的宇树运动策略。

音效在模型外工具栏点“开启音效”，默认关闭；A 仍用于开始/继续驾驶。`DriveRig.footfalls` 只含当前帧完成的脚步，暂停/复位清空；`DriveSoundTracker` 无论开关都更新状态，只对真实事件发短音，不在解静音时补播历史事件。`DriveSoundBank` 合成短落脚噪声/低音及操作提示音，复用一次噪声缓冲，声音结束后断开节点，同时发声上限 16，障碍警告间隔至少 0.8 秒。`DriveAudio` 独立管理显式用户手势、静音、后台中断与权限失败；不影响控制和得分。点击关闭会停止节点并挂起音频上下文，窗口失焦/后台后需点“恢复音效”；权限等待 1.8 秒仍不完成时恢复重试入口。音效为网页示意，并非实机录音。暂不加音乐或额外三维特效。

## 游客操作

页面提供两种体验，默认进入“发现挑战”。“自由观察”可以点选或拖动任意开放部位，也能直接播放左腿运动链，不需要先解锁；保留真实的简化质心/碰撞提示，但不触发倾倒，也不记发现进度。“发现挑战”按下方三步探索：点击就能看见动作，找齐案例后解锁协同演示，手动越界仍可触发倾倒。切换体验会复位姿态、保留已有挑战进度；观察中的播放不会完成挑战任务。

教学微动作有独立来源标记：约 0.3 秒转出 6°、停留 0.35 秒、0.45 秒收回。简化支撑分析可能因单脚接触改变而越界，但该教学片段只呈现分析，不累计半秒倾倒惩罚；回到手动摆出的姿态后恢复手动判定。连续重播沿用原始姿态，不累加 6°。视图内即时显示部位名称、作用与动作进度，“再看一次独立动作”可重复比较。

展厅设备参数与来源见 [屏幕与浏览器记录](../../docs/exhibition-context.md#屏幕与浏览器记录)。顶部切换模式，中间显示模型，下方双列显示当前任务和操作。`kiosk-layout.css` 使用百分比高度与 Flex 分配整个视口，兼容不支持 `dvh` 的旧版 Chrome；操作区按内容高度展开，模型使用剩余空间，操作面板不设置内部滚动。训练任务和微调控件同排，评分、提示和通关反馈均显示在模型区域外。姿态分析默认折叠，展开后仍保留质心图、碰撞和范围参考。沿用原浅绿配色、动作与拖动逻辑，无新增动画库或外部资源。`model-notes.css` 保持说明文字不遮挡模型，模型上仅保留方向箭头与位置圆点。执行 `node test/g1-kiosk-layout.cjs` 验证旧版视口单位兼容、内部无滚动、按钮无裁切、13 个动作、提示/成绩/通关、全屏切换与目标布局。

单击模型部位会选中一个独立自由度，呼吸高亮对应部件，做一次约 6° 的微小示意动作并回到原角度，同时平滑聚焦到便于观察的一侧。拖动只控制这个关节，不自动联动其他关节。拖动左脚控制左踝俯仰，左小腿控制左膝屈伸，大腿外壳选择对应髋俯仰轴。外壳是选择附近轴的交互代理，不表示只有一个轴。这是位移到角度的映射，不是完整 IK。

拖空白转视角，滚轮/双指缩放。部位操作使用 pointer capture，拖到画布外或取消操作时恢复视角控制，拖动不识别为点击。开始探索或下拉框选择可直接摆姿，但不计入模型上的发现进度。需要帮助时点“提示一下位置”，会定位下一个未找到的部位；点击模型或绿色标记均可发现。

目前开放 23 个独立控制：双腿各髋俯仰/膝屈伸/踝俯仰，腰部三个轴，左右肩/肘/腕各七个关节。下拉框可选择被遮挡的轴。拖动不自动聚焦，避免相机在操作中移动。“全身复位”清除摆姿并解除失衡，保留本轮发现进度；“重新探索”同时清除进度。

#### 歪腿修复、四模式与八个动作（2026-11-05，本地待实体试玩）

用户反馈“腿歪、除前进外其他方向腿不动”。实际 GLB 连续横移/倒退/转向采样发现：IK 对处于上限的关节仍取正向差分，被限位夹成同一角度，雅可比列归零，关节无法从饱和位置恢复；旧 reset 也没有清除各轴角度。现改为限位处向内差分，复位立即恢复关节，降低中立屈膝幅度，并让停止后左右脚重新落到对称站位。回归覆盖同一模型连续六次换方向，双腿都有明显屈伸，站稳后髋侧摆/旋转回到 1°以内，左右膝对称。

页面顶部增加四模式：**行走、锁定站立、阻尼示意、动作表演**。只有行走模式允许平面移动/转向，站立和表演可执行原地动作；阻尼示意取消当前动作、缓慢放下双臂，暂不接受动作。所有模式切换先停止移动、清除旧动作，重新要求摇杆回中，任务进度保留。阻尼的腿部仍有网页虚拟支撑；**不模拟实机进入阻尼后的失稳或失去主动位置支撑，不能据此学习实机站立操作**。

动作分组菜单有挥手招呼、伸手握手、邀请指引、礼貌鞠躬、拍手鼓掌、双臂上举、舒展双臂、左右律动；A 从固定挥手改为执行当前动作，X 仍快捷邀请。完整动作结束才可能完成匹配的接待任务，其他动作不发任务分。左右律动加入小幅骨盆下降，通过脚踝锚点求解双腿屈伸；上肢沿用平滑连续播放器，切模式从当前角度缓慢回收。固定橡胶手没有手指动画，握手和鼓掌均为教学编排。

### 三步发现游戏

1. 在模型上找到左髋、左膝、左踝三个俯仰/屈伸案例，逐个点亮发现卡片。同一个部位重复点击不会重复计数；左腿实际自由度不止这三个，本案例选取三个便于比较的轴。
2. 找齐后解锁“演示整条链”。可选轻屈膝 30° 或协同下蹲 45°：从当前姿态平滑回站姿，播放髋—膝—踝补偿与对侧支撑，再回到站姿。只在完整播放后进入挑战；“停止演示”或拖动会中断并回到独立模式，不算完成演示。整链高亮只改变显示，不启动联动。
3. 单独拖动左髋向前摆约 65°，观察质心脱离支撑范围。连续越界超过 0.5 秒后模型沿失衡方向逐渐倾斜 15°，显示“失去平衡”，点复位继续。普通碰撞重叠不触发失衡倒计时。链条演示期间显示平衡分析但不触发挑战倾斜。

### 动作训练与评分

在“发现挑战”底部点击“做个动作，赢颗星”，无需先完成寻找任务。首次进入默认是“抬起小臂”，游客只需拖动右肘一个自由度；调到手靠近身前就能获得第一颗星。随后可以在选关菜单中探索挥手招呼、双臂迎宾、向前递物、屈膝准备、抬脚跨步、举手致意、双手加油、伸手指路、礼貌鞠躬、转身介绍、双臂准备、翻掌展示等 12 个多关节动作。前三关另以入门、进阶、协同卡片推荐。点“观看示范”可观察动作；示范不能提交或得分。

点击“开始摆姿”，入门关无需先选择自由度；后续动作点击一个部位，再按住模型上跟随视角的方向提示拖动。同一手臂的外壳和手掌均可控制当前选中的肩、肘或腕轴；选中腿部自由度后可拖对应腿。拖动方向按当前相机投影计算，另外提供每次 3° 的方向微调按钮，部位按钮可用方向键微调。训练只开放当前动作使用的真实轴。

游客自己决定何时点击“提交动作 · 评估分数”。未手动调整、鼠标仍在拖动或伺服还未停稳时不能提交。评分只读取停稳的实际关节角度。每个目标轴按绝对误差 / 60°（上限一）形成误差比例，以平均误差的 60% 加最大误差的 40% 扣分，避免多轴平均掩盖一个严重错误；其余关节偏离零位超过 8° 时再按最大超差扣分。换算为 0～100 分、取整后，80 分表示动作达成、90 分动作熟练、98 分精准复刻；低分也给出评价。有限 OBB 若存在重叠，另外扣 25 分且成绩最多 79 分，明确提示碰撞，允许继续修改。不依据相机角度或滑块目标评分。

提交后最多获得三颗星。低分反馈指出偏差最大的部位，并用“向前抬一点”“伸直一点”等动作描述方向；点击“调整这个部位”会保留当前姿态并选中它，允许继续试而不锁关。通过后可重练或换关。每关只保存本机最高分，13 关上限 1300 分。纪录存在 localStorage 的 g1-motion-training-best-v2 中；旧版可见答案、自动保持规则的 v1 纪录不混入新成绩。没有服务器排行榜或身份校验，清除浏览器数据会删除纪录。

“需要一点提示？”由游客主动打开：第一次给非数值的动作线索；第二次显示金色目标轮廓和进一步线索，之后可收起或重开轮廓。腕部目标附掌面方向标记。切换任务、重新开始或观看示范会清空提示并隐藏轮廓；继续调整保留本次提示。提示不扣分，提交点评会说明是否借助提示，不泄露精确目标数值。

训练只评姿态匹配：支撑脚按几何锚点维持位置，质心与有限碰撞分析仍更新，平衡越界不触发倾倒、不影响姿态分；需要体验倾倒时返回原边界挑战。目标轮廓为轻量线段与圆点，不增加第二份机器人网格；支撑锚定是教学近似，不构成完整 IK、动力学或实机运动认证。

动作和提示配置在 src/motion-challenges.ts；纯评分及提交状态机在 src/pose-trainer.ts；目标轮廓在 src/target-pose-view.ts；UI、纪录和提交在 src/training-panel.ts。src/training-drag.ts 提供训练专用肢体/轴映射，src/freedom-interaction.ts 注入该映射并保留原模式拾取。src/pose-chain.ts 的 demonstratePose 播放全姿态示范、previewPose 临时采样后恢复、maintainSupportAnchor 维持支撑脚位置。src/knee-demo.ts 接入手动输入、提交时即时安全分析及原有模式。布局在 training.css，主要按 1080×1920 竖屏设计。

独立输入采用 `1-exp(-dt/0.12)` 的时间无关阻尼，滑块表示目标角、读数表示当前角。微动作和链条切换使用完整姿态平滑插值；屈膝段每帧按插值后的膝角重新计算几何补偿，保持支撑脚接地。上身的独立姿态在链条演示中保留。

此模型 `head_joint` 为固定连接，头部没有独立颈部自由度。点击头部会说明固定结构，建议通过腰部改变朝向，不人为添加不存在的关节。固定橡胶手映射到对应手腕旋转轴。

## 联动与警告

六个关节参与联动：左髋俯仰为左膝角度的 −0.4 倍、左踝俯仰为 −0.6 倍，使脚掌在关节限位允许的范围内保持接近水平。由左脚抬升量计算骨盆下降目标（最多 8 cm），再求解右膝支撑角度（搜索上限 80°，右髋/右踝各为其 −0.5 倍），平移骨盆以保持右脚位置。配置集中在 `src/interaction-config.ts`。这是几何联动预设，左脚可能水平滑移，没有完整的双脚接触逆运动学。

限位读取 GLB 中保留的官方 URDF 数据：`left_knee_joint` 为 −0.087267 至 2.8798 rad，界面约显示 −5° 至 165°。角度相对模型零位计算，保留原安装姿态。URDF 轴 `(0,1,0)` 随 Blender 导出坐标映射为 glTF `(0,0,-1)`，局部关节旋转只作用于下游部件。网页直接控制节点，无需重新导出 Blender 工程。

左膝可完整探索机械限位约 −5°～165°。肩肘另有教学交互限位，与各关节 URDF 机械限位取交集，统一作用于滑块、键盘和部位拖动：肩俯仰 −90°～90°；左肩侧摆 0°～100°，右肩侧摆 −100°～0°；肩旋转 −80°～80°；肘屈伸 0°～120°。这份模型的肘机械上限约 120°，不会照搬 150°。这些是展项交互默认值，不是人体生理测量或实物安全范围。配置保存在 `interactionLimits`，原始机械值保留。

平衡越界和代理盒重叠不收窄关节拖动范围；达到肩肘交互限位则停在该边界。越界先显示红边和轻微晃动，持续超过 0.5 秒后倾斜并等待复位；短暂越界可收回动作。碰撞重叠也有红色提示，但不算失衡。HTML 提示通过每帧世界坐标投影跟随冲突 link（优先重叠与当前关节影响的运动链）；限位提示跟随所选部位，平衡提示跟随质心位置，视锥外隐藏。

减少动态效果偏好关闭装饰入场、进度弹动、相机动画、晃动与倾斜；游客主动触发的独立动作和链条教学仍可播放，保留静态警告。晃动/倾斜是独立显示层，计算与改姿态前清除，不改变关节角度或质心判断。沿支撑边界指向质心的方向倾斜，并检查脚底最低点，必要时抬高显示模型以避免插地。切到后台清空越界计时并暂停渲染；教学微动作保留时间线和原姿态，回来继续收回；链条演示与手动伺服暂停，不累计后台时间。

三层范围仍作参考：“机械限位”来自当前所选关节的 URDF；“支撑建议”初始化时按 5°步长扫描默认屈膝预设，计算质心投影与接地脚底包围盒的支撑凸包，取与零位连通的区间；“碰撞收窄”再与有限碰撞检测结果求交，当前默认合并参考约 −5°～60°。这两行明确标为“初始屈膝参考”，摆动上身后不代表当前姿态的建议范围，也不限制操作；“当前可拖范围”显示机械限位与教学交互配置的交集。姿态观察、质心图和碰撞提示则实时更新。

碰撞检查 18 组关键组合：保留四组腿部，增加左右小臂/腕与躯干、左右大腿与躯干、左右大臂/小臂与两侧大腿。大臂对应 `shoulder_yaw_link`、小臂对应 `elbow_link`，各 OBB 只从 link 自身网格构造，不把整条子树包进去。复杂手指、双臂互碰等没有全量覆盖。代理盒按配置缩小以避开连接外壳，原模型网格不变；接近时橙色提示，重叠时警告但不锁定动作。代理盒可能误报或漏报，不能当作精确网格碰撞或完全防穿模求解器。

画面显示质心、地面投影与支撑多边形，侧栏补充俯视图。质心使用导出的 URDF 质量和局部惯性质心；缺失质量时退回整机包围盒中心并标注近似。运动时平衡/碰撞按最高 10 Hz 更新（切换、复位会立即刷新）；呼吸灯、运动和渲染按动画帧更新。移动达到 5 px 或超过 300 ms 的手势不会触发点击，部位拖动无长按时限。

辅助显示：膝角弧线半径缩至 13 cm，计入末端延长线后根据当前世界高度/旋转自动缩小，保持离地留距；弧线、角度指针、质心连线和投影点开启深度遮挡，避免透过脚和躯干。地面投影球改为平面圆点；支撑轮廓从接地脚底高度加几毫米偏移绘制，不随抬起的脚升高。侧栏保留不受遮挡的俯视图。

2026-11-04 连贯性调整：播放器改用预计算的保形三次 Hermite 曲线，同向经过关键姿势时共享角速度，避免每个关键帧都减速到零再启动；换向与显式停留处才停下，首尾从静止平滑起落。曲线逐轴不超出相邻作者姿态范围，仍按实际经过时间推进，低帧率不拉长动作。迎宾、邀请、指引等重复姿态的停留缩为 0.24 秒，保留展示意图。运行时复用姿态输出、预计算切线和总时长，避免逐帧构造关节集合和累计时间数组。

这些动作是教学编排，没有实机控制。关节仍取 URDF 与交互限位的交集，保留支撑脚几何锚定和限频的质心/有限碰撞提示；编排期间不触发发现挑战的强制倾倒，也不把教学近似称为实物安全认证。编排内的姿态分析只显示全身支撑与有限碰撞，不显示与当前表演无关的初始左膝扫描区间；返回关节探索后原范围显示恢复。真实 GLB 的动作关键帧和连接采样检查了限位、脚底高度与既有有限碰撞代理，不等于全网格、动力学或实体安全验证。

## 安卓运行性能

三维画布默认不超过 CSS 像素密度和约 100 万绘制像素，避免高 DPI 屏幕超采样；HTML 文字、按钮尺寸、拾取坐标和游戏规则不受影响。持续运动掉帧时分阶段小幅降低三维分辨率，最低为初始线性分辨率的 65%，不改变动作播放时间。绘制最高 60 Hz，无选中部位、无相机运动的静止画面停止重复提交 WebGL 绘制；选中时保留呼吸灯动画。

任务文案只在状态变化时同步，角度文字只在显示值变化时同步。支撑求解仅更新需要的父子路径，平衡连线重用几何缓冲；平衡与碰撞仍按原最高 10 Hz 分析，训练动作和评分不改。以上减少运行负担，实体安卓 Chrome 的最终流畅度仍需现场验证，不以本机测试推断现场帧率。

执行 `node test/g1-performance.cjs` 验证重复 DOM 更新、静止方位文字和高 DPI 画布预算；执行 `node --test test/g1-runtime-cost.test.js test/g1-render-budget.test.js` 验证支撑接地、显示倾斜恢复、几何重用及自动分辨率策略。

## 展厅全屏

模型工具栏的全屏按钮会请求整个网页进入浏览器全屏，并请求隐藏浏览器导航栏。若浏览器或访客手势退出全屏，页面会显示“返回全屏”按钮，必须由访客再次点击；浏览器安全规则不允许网页静默强制重进全屏或拦截系统手势。要求设备无法退出网页时，需在安卓设置应用固定/kiosk 模式，并关闭系统导航或通知手势。

## 重新生成

1. 在 PowerShell 中执行 `./tools/get-g1-assets.ps1`，下载该样机引用的文件到被 Git 忽略的 `source/`。
2. 在根目录执行 `& 'D:/Blender/blender.exe' --background --factory-startup --python tools/build-g1-model.py`，路径按实际安装调整。
3. 修改网页逻辑后，在本目录执行 `npm ci` 和 `npm run build`，生成本地 `app.js`。

依赖版本在 `package-lock.json` 固定。Three.js 0.160.1，esbuild 0.25.12；打包目标为 Chrome 88，实体展厅设备的 WebGL 支持和性能仍需现场检查。
