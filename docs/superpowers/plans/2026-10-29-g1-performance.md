# 安卓展厅 G1 运行性能优化

目标：优化加载完成后的拖动、演示和训练流畅度，保留原游戏规则、动作、警告和已确认的布局。

设备信息：屏幕内置安卓 Chrome，CSS 屏幕 1080×1920，视口 1080×1800，DPR 2。尚无设备帧率或 GPU 性能记录；本机 Edge 的 CPU 节流数据只用于前后对比，不推断实体设备 FPS。

已采集基线：`node work/g1-performance/measure.cjs baseline`，本机 Edge，4 倍 CPU 节流，真实模型。关节动作任务文字重复写入，训练多次覆写同一段引导；每帧提交约 23.6 万三角面。原始 JSON 存于工作目录，不发布调试脚本。

- [x] 性能采样与 `test/g1-performance.cjs` 创建运行时回归，先验证它会捕获重复 DOM 更新。
- [x] 先验证重复界面同步是否导致额外主线程开销；缓存未变任务与文字，保持关节运动逐帧、文字按可见值更新。
- [x] 通过等价性测试缩短重复世界矩阵计算路径，重用平衡辅助几何；不降低警告计算频率或改评分。
- [x] 限制安卓三维区域的超采样，必要时自动调整分辨率；HTML 字体、页面尺寸与拖拽坐标不变。
- [x] 真实模型单元测试、性能采样前后对比、发现/失衡/十二训练动作浏览器回归、竖屏视觉检查。

实现范围：`src/knee-demo.ts`、`src/main.js` 为界面与绘制入口，独立 `src/render-budget.ts` 定义像素预算；`src/warning-feedback.ts`、`src/pose-chain.ts`、`src/balance-visualizer.ts` 只优化等价计算。无需修改平衡分析算法。模型文件和动作配置不改。构建更新 `app.js`；页面脚本版本参数让旧访客刷新后获取新构建。

## 验证结果

- `npm run build` 成功，`node --test test/*.test.js` 87 项通过。
- `test/g1-performance.cjs`：原实现同一次动作重复更新任务文字 94 次，新增测试先失败；优化后通过，并验证关节实际到达指定角度。
- `test/g1-runtime-cost.test.js`：全树矩阵更新从一次求解 13 次降至 1 次，支撑脚保持接地；无警告时 120 轮显示清理从 240 次全树更新降至 0 次；质心连线重用原几何。这三项先失败后通过。
- `test/g1-render-budget.test.js`：验证像素上限、持续慢帧降级、后台/闲置不误降级。
- 浏览器 `g1-experience.cjs`、`g1-training.cjs`、`g1-demo.cjs`、`home-integration.cjs`、`g1-performance.cjs` 通过。保留教学动作不误倾倒、手动失衡、两种模式、十二套网格拖动动作/评分/提示/纪录，以及旋转和导航。
- 视觉复查真实模型、1080 竖屏训练和测量截图，无新布局裁切。

同机 Edge、1080×1800、DPR 2、4 倍 CPU 节流，约两秒采样窗口：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 闲置 DOM 更新/秒 | 490 | 0 |
| 关节操作 DOM 更新/秒 | 2227 | 223 |
| 训练演示 DOM 更新/秒 | 3419 | 188 |
| 闲置重复 WebGL 提交 | 持续 | 0 |
| 默认画布绘制像素 | 1480×1155 | 987×770 |

测量脚本的 frames/fps 统计的是全部 rAF 回调（包括被帧率上限跳过的回调），不能作为显示帧率；drawsPerFrame 也因分母含跳帧而不作为单次绘制复杂度对比。模型几何不变。CPU 时间受本机负载影响，不据此宣称实体设备提速倍数或 60fps。实体安卓设备尚待现场验证。
