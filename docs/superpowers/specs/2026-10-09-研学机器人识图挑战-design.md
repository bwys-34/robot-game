# 研学「机器人识图挑战」— 设计文档

日期：2026-10-09
状态：已获用户批准

## 目的

研学活动现场有一面**机器人照片墙**（150 台机器人）。小朋友看完照片后，扫二维码用手机打开本游戏，玩「看图选型号」的 10 题挑战，系统记录**用时与正确率**，答完在手机上看到自己的成绩。现场要让多个小朋友**快速轮流**体验。

本设计**直接覆盖**现有 `robot-game` 项目（旧的 182 台版本只保留在 git 历史中，需要时可回滚）。

## 场景与约束

- 现场照片墙上每张照片标注 `编号 + 品牌 + 型号 + 年份 + 国家`，供小朋友先看先记
- 玩：手机扫码 H5，静态托管（GitHub Pages），**纯前端、无后端**
- 成绩**只存在本机**（localStorage / 内存），不上传、不留存
- 核心诉求：**快**——每局短、无回退、答完即走

## 已确定的需求（用户逐项确认）

1. 交互形态：**手机扫码 H5（联网访问托管页）**
2. 玩法与计分：**固定题数计时**——每局 10 题四选一，记录总用时 + 答对数
3. 数据去向：**只需本人看成绩**（无后端、无排行榜、无账号）
4. 题目形式：**看图选机型名**（照片 + 4 个型号名选项）
5. 干扰项：**随机**（从全库 150 台随机抽 3 个，排除正确项）→ 偏易，适合低龄、节奏快
6. 落地位置：**直接覆盖原 robot-game**
7. 模式精简：**只留「答题 + 结果」**，删除旧的学习模式 / 品牌选择页 / 照片匹配页
8. 答题反馈：**只闪一下对错、不停留**，保持节奏

## 范围

**做**：换数据、换照片、10 题计时四选一、结果页、二维码、部署、测试。

**不做（YAGNI）**：后端、排行榜、账号/昵称、学习/图鉴模式、品牌选择页、照片手动匹配页、答题记录导出、分类/特点等新表没有的字段。

## 数据设计

### 数据来源
- `人形机器人族.xlsx`（D 盘照片墙目录内），字段：序号 / 公司 / 产品名称 / 推出年份 / 国家 / 官网链接
- 共 **150 台**（序号 1–150）

### `data/robots.js`
每条：`{ no, brand, model, year, country }`
- `no`：字符串 `"1"` … `"150"`（与照片文件名数字对应）
- `brand` ← 公司，`model` ← 产品名称，`year` ← 推出年份，`country` ← 国家
- 旧版有、新表没有的 `category` / `subcategory` / `feature` **删除**，不留空字段

### `data/photos.js`
照片文件名清单（顺序 1 → 150）：`["1.jpg", ..., "150.jpg"]`

### 照片处理
- 源：`D:\...\6. 照片墙\6. 照片墙\` 下 5 个子目录（`1-30` / `31-60` / `61-90` / `91-120` / `121-150`）
- 真实照片文件名形如 `24. Unitree [Unitree H2] 2025 中国.png`（编号 + 描述），**按开头编号取号**
- 每个子目录里另有一个无描述的封面文件（`1.jpg` … `5.jpg`）——**过滤掉**，只取「编号 + 描述」的文件
- 统一转 **JPEG（最长边 1200px，质量 82）**，命名 `<编号>.jpg`（`1.jpg` … `150.jpg`）放入 `photos/`
- 原图保留在用户源文件夹，不动

## 出题与计分逻辑（`js/quiz.js`）

- 每局：从 150 台里**随机抽 10 题**（题不重复）
- 每题：`makeOptions(correct, all, 3, preferSameBrand=false)` → 1 正确 + 3 随机干扰，打乱顺序
- 计时：`performance.now()`——记录每题用时与总用时
- 计分：答对数 / 10 → 正确率 = 答对 ÷ 10
- 结果：总用时、答对题数、正确率、每题平均用时

## 界面结构（单页三态）

`index.html`（HTML/CSS/JS 单文件，复用旧版架构与视觉风格）：

1. **首页**：标题「机器人识图挑战」+ 一句话玩法（看照片 → 选对型号 → 10 题计时）+「开始挑战」按钮
2. **答题页**：顶部「第 X / 10 题」+ 实时计时；中间大图；下方 4 个型号名按钮；点选后**闪一下对错**（正确绿、错误红并标出正确项），随即进入下一题，**不可回退**
3. **结果页**：总用时 / 答对 X/10 / 正确率 / 每题均时 + 一句鼓励语 +「再来一局」

- 竖屏优先、响应式、大按钮（手机好点）
- 照片加载失败时回退占位框（沿用旧版 `onerror` 处理）

## 文件结构

```
robot-game/
├── index.html          ← 首页 / 答题 / 结果，单文件
├── js/quiz.js          ← 纯逻辑（UMD，Node 可测）：shuffle / makeOptions / buildOrder
├── data/robots.js      ← 150 台 {no,brand,model,year,country}
├── data/photos.js      ← 照片清单 ["1.jpg"... "150.jpg"]
├── photos/             ← 150 张压缩后 JPEG，命名 <编号>.jpg
├── test/               ← node --test 用例（更新为 150 台）
└── docs/superpowers/specs/  ← 本设计文档
```

## 数据流

1. 载入 `data/robots.js` + `data/photos.js`
2. `Quiz.buildOrder(PHOTO_LIST, ROBOTS)` → 配对「照片 ↔ 机型」，匹配不到的跳过
3. 随机抽 10 题 → 逐题 `makeOptions` 生成 4 选项
4. 渲染照片 + 选项，点击记录对错与用时
5. 10 题结束 → 结果页

## 边界与错误处理

- **照片缺失 / 编号对不上**：`buildOrder` 按 `no` 匹配，匹配不到的机型自动跳过，不报错
- **全库不足 4 台**：150 台远够，无需特殊处理
- **手机屏幕**：竖屏优先，宽屏（电脑/平板）居中限制最大宽度
- **首次加载需联网**：静态资源从托管站点拉取；不做离线缓存（超出本次范围）
