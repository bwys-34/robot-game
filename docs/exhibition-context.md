玩法入口增加「驾驶考场」「舞台挑战」，键盘、触屏及现有电脑/安卓归一化手柄继续共用规则。仍是先本地体验，未提交、推送或发布；本地入口 `http://127.0.0.1:8765/demos/g1/drive/?v=2026-11-10-course-stage-1`。工作分支 `codex/g1-course-stage` 从现有未发布成果接续，其他探索及档案工作不属于本轮。

考场：经庭院入口到起点 → 依次绕桩（含两个转弯辅助路标）→ 从两根柱之间实际穿过窄门 → 到准备圈面向展厅、停稳 0.6 秒 → 向后倒入 P 位并停稳 1 秒。朝向容差 15°，倒车累计至少 0.45m；门洞检查按机器人半径收窄，绕柱到后圈不会通过。碰撞可起身续关；暂停、瞬移不能计入路线。评分为路线 40 / 停车 25 / 朝向 15 / 稳健 20，倒地每次扣稳健 8 分，各项最低 0，不计速度奖励。

舞台：沿路标从侧门到 H 圈 → 明确挂接 → 切阻尼或零力矩、进入调试 → 保存前三个 RB 动作为本场节目 → 恢复站立并解挂 → 穿庭院到舞台中心 (6.3,8.25) → 面向展厅和观众停稳 → 动作表演模式中依次完整播放三段。节目支持重复动作。预览、错误动作、中断或暂停过的片段不能获得完成分；离台后须重新就位，已完成片段保留。成绩完成后冻结。评分为准备 20 / 路线 20 / 就位 15 / 演出 30 / 稳健 15，倒地每次扣稳健 8 分。

实现为 `drive-course.ts` / `drive-show.ts` 独立状态机、`drive-challenge-panel.ts` 操作台、`drive-campus-visual.ts` 轻量庭院；相机全景扩展到庭院，小地图按宽高共同缩放。任务卡位于模型外，吊机与调试时用紧凑任务提示。仅构建 `npm run build:drive`。自动化检查脚本为 `test/g1-drive-challenges.cjs`，支持 `CHALLENGE_SOURCE=manual/desktop/android`、`SHOW_ONLY=1`；截图和报告放在 `work/g1-course-stage/`。开发 Edge / 模拟手柄不能代表实体 Android 11 / Chrome 88 的帧率、触控和手柄验收。

节目确认后，仍在吊架调试时再次保存或恢复默认，会同步更新本场节目与 RB 快捷键；首次恢复默认仍须点保存确认。未完成演出时返回吊架重新挂接，会清空旧节目、路线、就位和演出进度，保留用时与倒地记录；已经完成的成绩不变。浏览器存储失败仍允许本次节目生效，面板提示不会持久保存。

1. 驶入 H 圈（-1.25, -1.5），松杆停稳 0.8 秒，按 A（键盘 H 或屏幕按钮）明确挂接。双吊带用 1.15 秒收紧，显示「支撑有效」后才有保护。

5. 点「站稳，准备解挂」，恢复站姿稳定 0.5 秒后按 A，用 0.75 秒落脚解挂；再恢复行走或切表演，用新 RB 组合键播放。吊带未解开不得直接行走或表演。

## 历史问题与维护重点

### 竖屏底部留白、操作区需要滚动

曾使用仅依赖 `dvh` 的高度与固定空间分配，部分浏览器表现为按钮裁切、操作面板滚动、页脚下留白。训练控件还曾被放在任务区的下一行。

现有 `kiosk-layout.css` 使用百分比高度、Flex 外壳和“模型剩余高度 + 操作区内容高度”的 Grid；覆盖训练模式的最小高度，训练任务与控件同排，操作面板不设内部滚动。丢弃 `dvh` 声明的测试用于模拟一种旧浏览器限制，不能据此认定现场 Chrome 必然不支持 `dvh`。

验收同时检查控件相对视口的位置、祖先元素裁切、内部滚动、页脚位置及模型可用高度。仅检查整个文档的 `scrollHeight` 不足以发现此类问题。

### 操控部位后无法转视角

安卓触屏曾在部位拖动后连空白背景也无法旋转，电脑正常。修复通过 `src/orbit-gesture-guard.ts` 清理 OrbitControls 遗留触点，并处理取消、捕获丢失、窗口失焦和切后台。维护时复测部位拖动后再转视角、双指两种松手顺序及操作中断。

### 安卓运行卡顿

用户接受首次加载较慢，更关心进入后的持续流畅度。现有优化包括绘制像素预算、动态三维分辨率、静止时减少绘制、减少重复 DOM 更新和平衡/碰撞分析限频。保留这些策略，尤其避免按 DPR 2 无上限提高 WebGL 分辨率。不要仅凭换域名或桌面测试承诺提升现场帧率。
