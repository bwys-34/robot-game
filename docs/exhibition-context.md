## 表演同步音效与转向跟随修复（2026-11-07，本地预览，尚未发布）

用户要求动作表演配对应声音，并反馈画面不再随机器人转向。最新驾驶页本地缓存为 `2026-11-07-performance-audio-2`，覆盖下节 gait-audio-1 预览；本轮未授权发布，线上仍为下文 visitor-console-1。

- 十五个动作均加入与姿态时间线同步的音效：四种舞蹈分别为鼓点、机械节奏、旋律轻拍和加油拍手；挥手、握手、邀请、鞠躬、上举及舒展配轻机械音或提示音；鼓掌在三次双手合拢时发声，跳跃/后空翻按起跳、腾空和落地发声，蹲坐跟随下降和起身。没有外部音乐文件或独立节拍定时器。
- 新增 `drive-action-audio.ts`，按实际动作时间消费当前帧音效，卡帧时丢弃过期提示，避免补播爆音；暂停、切模式、倒地、复位会取消当前表演声音，正常结束保留短尾音。开启/恢复音效仍需触摸或鼠标点击工具栏；默认静音。

## 手脚联动与音效（2026-11-07，本地预览，尚未发布）

用户在教学与手柄体验方案中选择先实现手脚联动、音效。本轮只修改驾驶页，音乐、教学观察层和新任务尚未加入。预览缓存标记 `2026-11-07-gait-audio-1`；当前线上版本仍按下节已发布记录，不能把本地构建视为上线。

- 前后行走由机器人局部坐标下的左右脚前后差驱动对侧摆臂，修复世界 Z 坐标导致换朝向后摆臂减弱的问题。肩部摆幅最多约 ±20°（围绕原站姿），肘部跟随屈伸；侧移、转向、持续踏步使用实际摆脚相位的小幅上肢动作，停止后阻尼回收。参数集中于 `DRIVE_GAIT_CONFIG`；属于教学编写的运动学步态，不是宇树实机策略或实测轨迹。
- 场景工具栏增加“开启音效”，默认静音，不影响原 A 启动。点/触开启后，实际摆脚完成才触发左右落脚声；开始、暂停、模式/速度切换、动作启动、接待进度和靠近障碍有短提示音。均为本地 Web Audio 合成音，无音频下载或背景音乐循环。
- 音效不参与输入、姿态或评分。静音清理声音节点；失焦/切后台即静音并暂停音频上下文，回来显示“恢复音效”，需再点。手柄轮询不能被当作解锁音频的可靠浏览器手势。权限等待超时显示重试按钮，音频 API 缺失时继续无声驾驶。
- `drive-rig.ts` 每帧输出实际落脚事件，`drive-audio.ts` 分离状态边沿检测、短音合成及权限/生命周期；复用噪声缓冲、限制同时发声数并释放节点，警告限频。没有新增渲染特效或改变两套手柄映射。
- 开发电脑 Edge：179 项单元测试及驾驶面板/安卓通道模拟回归通过；音效回归使用真实 Web Audio 与 OfflineAudioContext 检查可听波形、结尾静音、节点释放、开关/后台/权限超时/不支持降级，以及五种视口工具栏。实体安卓扬声器音量、蓝牙与设备帧率仍待现场测试。

## 历史问题与维护重点

### 竖屏底部留白、操作区需要滚动

曾使用仅依赖 `dvh` 的高度与固定空间分配，部分浏览器表现为按钮裁切、操作面板滚动、页脚下留白。训练控件还曾被放在任务区的下一行。

现有 `kiosk-layout.css` 使用百分比高度、Flex 外壳和“模型剩余高度 + 操作区内容高度”的 Grid；覆盖训练模式的最小高度，训练任务与控件同排，操作面板不设内部滚动。丢弃 `dvh` 声明的测试用于模拟一种旧浏览器限制，不能据此认定现场 Chrome 必然不支持 `dvh`。

验收同时检查控件相对视口的位置、祖先元素裁切、内部滚动、页脚位置及模型可用高度。仅检查整个文档的 `scrollHeight` 不足以发现此类问题。

### 操控部位后无法转视角

安卓触屏曾在部位拖动后连空白背景也无法旋转，电脑正常。修复通过 `src/orbit-gesture-guard.ts` 清理 OrbitControls 遗留触点，并处理取消、捕获丢失、窗口失焦和切后台。维护时复测部位拖动后再转视角、双指两种松手顺序及操作中断。

### 安卓运行卡顿

用户接受首次加载较慢，更关心进入后的持续流畅度。现有优化包括绘制像素预算、动态三维分辨率、静止时减少绘制、减少重复 DOM 更新和平衡/碰撞分析限频。保留这些策略，尤其避免按 DPR 2 无上限提高 WebGL 分辨率。不要仅凭换域名或桌面测试承诺提升现场帧率。
