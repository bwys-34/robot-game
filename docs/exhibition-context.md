# 展厅项目上下文

最后整理：2026-11-04。用于后续接手时先了解现场条件和已确认的需求。具体算法与完整操作说明见 [G1 README](../demos/g1/README.md)，全站使用说明见 [项目 README](../README.md)。

## 项目与使用场景

- 项目是机器人展厅游客互动网站：首页包含识图挑战、机器人档案馆和 G1 三维互动。
- 当前重点设备是展厅竖屏触摸大屏。优先服务短暂停留的游客，让人直接看见入口、操作与反馈。
- 用户已明确：识图部分不需要改。G1 布局维护默认保留现有游戏内容、评分规则和交互逻辑；修改范围由当次需求决定。
- 档案馆保留原有界面与年份信息，G1 沿用已确认的浅绿视觉风格。局部布局修复不扩大为全站改版。

## 已确认的 G1 界面要求

1. 页面上方放“自由观察 / 发现挑战”两个模式入口。
2. 中间是机器人模型，下面显示当前模式对应的任务和操作。
3. 展厅目标竖屏中，不需要滚动页面或内部操作面板就能看见相关功能；提示、微调、提交、成绩与通关状态均应检查。
4. 避免页脚下方出现大段无效留白；操作区按内容占高，模型使用剩余空间。
5. 说明、角度、警告和评分文字位于模型区域外，保持模型可见；模型上的方向箭头与位置圆点可保留。
6. 保留全屏按钮和退出后的“返回全屏”入口。浏览器全屏需要用户手势；设备级常驻全屏需安卓 kiosk/应用固定配合。
7. 保留拖部位摆姿、拖空白转视角、双指缩放、正/侧/背面快捷视角。
8. 用户希望先看本地效果，再决定上线。布局修改默认先提供预览；当次明确说“上线 / 推送”后继续发布，无需重复询问。

## G1 模型与玩法边界

- 展馆实机为 G1 EDU，无灵巧手。用户要求先按样机做演示，不要求等待机器编号。
- 当前网页样机采用官方 `g1_29dof_rev_1_0.urdf` 的导出模型，固定橡胶手；尚未逐项核对展馆实机配置。头部为固定连接，不能虚构颈部自由度。
- 当前保留“孤立关节控制”和“运动链联动演示”两层体验；发现挑战内含寻找案例、解锁协同演示和手动越界体验。
- 动作训练现有 13 关（一个单关节入门动作，加 12 个多关节动作）。游客手动摆姿后主动提交评分，提示由游客主动打开；不默认显示精确答案。
- 2026-11-04 新增本地“动作编排”试玩：用户确认在 3D 页面上部增加入口，使用迎宾、讲解、舞蹈与自由创作任务，十二个全身/上肢协同动作可编成最多四步；动作选择沿用分组菜单。单步预览自然收回，连续播放中段不归零，整套结束统一收回。
- 编排任务分按动作用途、顺序、方向及节奏计算，与原摆姿训练的精准度评分分开；自由创作给称号不打固定分。编排保留在当前页面会话内，切后台自动暂停。
- 2026-11-04 用户反馈表演卡顿、不连贯：查到旧播放器每个关键姿态都减速到零，重复姿态停留较长。本地改为保持角速度连续的保形插值并缩短展示停留，保留首尾收放、限位和有限碰撞/接地检查。实际安卓设备的掉帧仍需现场验证。
- 用户于 2026-11-04 完成本地试玩后确认“音乐先不急，先上线”。本次发布动作编排和连续播放优化，缓存版本 2026-11-04-performance-1，不加入音乐及新特效；上方的“返回关节探索”可回到原玩法，保留已选步骤。后续新增玩法仍按先本地体验、再确认上线的约定执行。
- 教学微动作、链条演示、自由观察和训练有各自的失衡处理规则，详见 G1 README。修改布局时保留这些区别，尤其不能让点击产生的教学微动作直接触发倾倒。
- 质心、支撑和有限碰撞均为教学近似，不代表实物安全范围，不连接实机。

## 历史问题与维护重点

### 竖屏底部留白、操作区需要滚动

曾使用仅依赖 `dvh` 的高度与固定空间分配，部分浏览器表现为按钮裁切、操作面板滚动、页脚下留白。训练控件还曾被放在任务区的下一行。

现有 `kiosk-layout.css` 使用百分比高度、Flex 外壳和“模型剩余高度 + 操作区内容高度”的 Grid；覆盖训练模式的最小高度，训练任务与控件同排，操作面板不设内部滚动。丢弃 `dvh` 声明的测试用于模拟一种旧浏览器限制，不能据此认定现场 Chrome 必然不支持 `dvh`。

验收同时检查控件相对视口的位置、祖先元素裁切、内部滚动、页脚位置及模型可用高度。仅检查整个文档的 `scrollHeight` 不足以发现此类问题。

### 操控部位后无法转视角

安卓触屏曾在部位拖动后连空白背景也无法旋转，电脑正常。修复通过 `src/orbit-gesture-guard.ts` 清理 OrbitControls 遗留触点，并处理取消、捕获丢失、窗口失焦和切后台。维护时复测部位拖动后再转视角、双指两种松手顺序及操作中断。

### 安卓运行卡顿

用户接受首次加载较慢，更关心进入后的持续流畅度。现有优化包括绘制像素预算、动态三维分辨率、静止时减少绘制、减少重复 DOM 更新和平衡/碰撞分析限频。保留这些策略，尤其避免按 DPR 2 无上限提高 WebGL 分辨率。不要仅凭换域名或桌面测试承诺提升现场帧率。
